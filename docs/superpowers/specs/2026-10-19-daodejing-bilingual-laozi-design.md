# 道德经中英注释展示 + 老子对话智能体 · 设计文档

- 日期：2026-10-19
- 性质：大创项目
- 风格基调：古风清雅（宣纸米底、朱砂印红、褐字）

## 一、项目概述

一个项目、两个协同模块，由统一的古风视觉绑定：

1. **道德经展示页**——八十一章中英对照 + 注释，沉浸式阅读。
2. **老子对话智能体**——以老子（老聃）人设，就经义答疑、借道解惑。

目标是大创答辩可用、可演示，代码结构清晰可维护，后续可平滑升级。

## 二、整体架构

### 技术栈
- 前端：原生 HTML / CSS / JS（轻量，可选 Vite，无框架）。
- 后端：前期无后端（纯前端直连大模型 API）；预留轻后端升级位。
- 大模型：国内模型（Qwen / DeepSeek / GLM 之一），古文理解好、国内访问稳。

### 可插拔接口层（关键设计）
把"调用大模型"封装成单一前端接口，三种部署方案共用同一套前端，后端可插拔：

```
对话界面  →  askLaozi(messages, {onToken})  →  ① 直连 / ② 轻后端 / ③ serverless
            (接口不变)                          (只换这一个函数的实现)
```

- **前期（方案三·直连）**：`askLaozi` 内部直接 fetch 大模型 API，Key 读自本地 `config.js`，走流式输出。仅用于本地/内网演示。
- **后期（方案一·轻后端 或 方案二·serverless）**：`askLaozi` 改为 `fetch('/api/chat')`，Key 与系统提示词搬进后端环境变量。**界面代码不变。**

### 密钥安全
- `config.js`（真实 Key）写入 `.gitignore`，不提交。
- 提交 `config.example.js` 模板（占位 `YOUR_API_KEY`），组员复制为 `config.js` 填各自 Key。
- 可上传私密仓库协作；Key 全程不入 git 历史。
- 升级到后端后，Key 迁入服务端环境变量，此习惯延续。

## 四、数据模型

语料来自两份 docx：
- 《老子道德经翻译语料库.docx》——81 章，每章中文原文 + 英文翻译。
- 《道德经注释英译(2).docx》——每章一段中文讲解 + 一段英文讲解（学术性章旨赏析）。

每章数据结构（`data/chapters.json` 为数组，81 个对象）：

```json
{
  "id": 1,
  "part": "道经",
  "title": "体道",
  "original": "道可道，非常道；名可名，非常名……",
  "translation": "The Tao that can be explained through language cannot be termed the eternal Tao……",
  "commentaryZh": "第一章可以看作是《道德经》整部书的前言……",
  "commentaryEn": "The first chapter may be regarded as a preface……"
}
```

字段说明：
- `part`：道经（1–37）/ 德经（38–81）。
- `title`：通行的传统章名（如一章"体道"、八章"若水"），从通行版补录。
- `original` / `translation`：来自文件一。
- `commentaryZh` / `commentaryEn`：来自文件二，对应该章讲解。

**解析注意**：文件一中原文与英译的分隔不完全规整（"英译"标签时有时无，章首编号偶有全角/空格差异）。实现计划第一步需写解析脚本，并逐章核对 81 章齐全、中英与注释对齐，产出干净的 `chapters.json`。

此数据同时作为后期老子智能体 RAG 的知识库。

## 五、阅读体验（展示页）

### 目录首页 `index.html`
- 顶部标题"道德经"，副标题引一句（"道可道，非常道"）。
- 八十一章宫格，**单一整列不分区**；每格显示章号 + 章名（如"一·体道"）。
- 点格进入阅读页；宫格轻悬停效果（朱砂印泛起）。
- 注：`part` 字段（道经/德经）仍保留在数据中，但目录展示不再按其分区。

### 沉浸阅读页 `chapter.html?ch=1`
- 一屏一章，原文居中大字，留白充足。
- 自上而下：章号章名 → **原文** → **英译** → **注释**（中文/英文讲解，默认收起，点"观注"展开）。
- 左上 ☰ 唤出**侧边抽屉**（81 章目录，当前章高亮，带章名），随时跳章；手机端自动收起。
- 底部"上一章 / 下一章"翻页，支持键盘左右键。
- 右下角悬浮**"问道"**钮；读某章时有**"问老子此章"**，带入当前章上下文。

### 状态
- 当前章记在 URL（`?ch=12`）和 localStorage：刷新不丢、可分享直达某章。

## 六、老子对话智能体

### 界面
- 悬浮"问道"钮唤出对话面板（右侧滑入抽屉，古风气泡）。
- "问老子此章"把当前章原文 + 译文 + 注释塞进上下文，回答贴着该章。

### 接口层 `askLaozi.js`（可插拔）
- 对外只暴露 `askLaozi(messages, { onToken })`，返回流式文本。
- 前期：直连国内大模型 API（读 `config.js` 的 Key），`stream: true` 逐字显示。
- 升级位：改 `fetch('/api/chat')` 即切后端，界面不动。

### 人设 `prompt.js`（系统提示词，前后期共用）
- **身份**：老子（老聃），自称"吾"。
- **语气**：半文半白——有古意、好懂，不堆砌生僻字；简练、点到为止。
- **讲经**：依《道德经》义理与五千言作答；被问具体章句时，引该章原文再阐发。
- **借道解惑**：用户诉说现实困惑（焦虑、内卷、得失、人际等）时，以道家义理（不争、知足、柔弱胜刚强、顺其自然、为而不恃等）温和开导，贴着对方处境给宽慰与指引，像通透的长者，而非复述经文，不说教。
- **边界**：书中未涉及或不知之事，坦言"此非吾所言"，不硬编、不假托现代知识装古人。

定调示例（非最终稿）：
> 用户：何谓"上善若水"？
> 老子：吾尝言，上善若水。水善利万物而不争，处众人之所恶，故几于道。人若如水，居下、不争、随形，则近道矣。

> 用户：我总怕落后别人，很累。
> 老子：汝所累者，非事也，乃"争"也。天下万物并作，各有其时，江河不争先而终归于海。不若少私寡欲，守汝之本真。知足者富，知止者安。弦绷太紧则断，人绷太紧则困。缓之。

## 七、演示亮点（核心之外，保持克制）

- **朗读**：阅读页"听"钮，用浏览器自带语音（Web Speech API）朗读原文，零依赖、零成本。
- **古风动效**：翻章淡入、注释展开渐显、宫格悬停印泛起，纯 CSS。
- **分享卡片**：某章或老子的一段话生成竖版古风卡片（canvas 绘制，可存图），便于答辩传播。

## 八、后期扩展（本期不做，预留位）

### 老子具象化形象
对话已通过 `askLaozi` 流式返回文本，加形象层为叠加式，监听同一套"消息/流式"事件做动作即可，现有代码几乎不动。按投入从轻到重：
- **① 静态立绘**：一张或几张古风老子立绘（不同神态按情况切换），纯图片，零技术难度。推荐起步。
- **② Live2D 动态形象**：会呼吸、眨眼、对口型的 2D 虚拟形象，原生 JS 可接（pixi-live2d-display），与技术栈兼容；主要成本是 Live2D 模型（约稿或买现成）。
- **③ 数字人 / 3D**：说话视频数字人（国内数字人 API）或 Three.js + VRM，最像真人但最重、有费用，对大创偏奢侈。
- **配套声音**：搭配 TTS（讯飞/阿里音色，或浏览器语音先顶）更活。

设计上预留"形象层"位置：对话模块对外广播说话开始/结束、流式进行中等事件，形象层订阅这些事件驱动动作。

### 智能体 RAG
后期把 `chapters.json` 作为知识库，老子回答时检索相关章节原文 + 注释作为依据，引用具体章节、减少编造。接入点在 `askLaozi` / 后端，前端界面不变。
